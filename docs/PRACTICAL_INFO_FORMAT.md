# 📚 PRACTICAL_INFO_FORMAT.md — 사연+실생활 정보 서브 포맷

> 최종 수정: 2026-07-14
> 사연 채널 채널에 기존 막장 사연과 **병행**하는 서브 트랙. 법률/금전/사기/폭력/절도누명/모함/사내정치 등 실생활 갈등을 다루되, 사이다 해결 뒤에 실제 대처 기관·방법을 짧게 붙여 "재미+실질 도움"을 동시에 준다.

## 배경

기존 사연 채널 사연은 순수 막장 각색(Sniper: 단일사연→단일영상)이 표준. 이 서브 포맷은 여기에 "실제로 이런 일 겪으면 이렇게 대처하고, 여기서 도움받으세요"라는 정보 레이어를 추가한 변형이다. 새 채널이나 새 스킬을 만들지 않고, **기존 `produce-sayeon` 파이프라인을 확장**해서 두 트랙을 하나의 채널·하나의 스킬로 병행 운영한다 (장점: 장기 데이터로 어느 쪽이 완주율/전환에 나은지 A/B 판정 가능 / 비용: 스킬·QC 이중화를 감수).

## 아키텍처 — 변경 지점 3곳만

기존 파이프라인(사연선택 → CVDE 스코어링 → 막장 각색 → 이미지생성 → Fish TTS → Ken Burns 렌더 → QC → upload-meta → 게시 도구)은 그대로 재사용. 아래 3곳만 확장한다.

### 1. 사연 선택 (draft-narration 이전 단계)

CVDE 스크리닝 시 다음 조건을 만족하는 사연을 "실생활 대처형" 후보로 우선 태깅:
- 갈등 유형이 법률/금전/사기/폭력/절도누명/모함/사내정치 중 하나
- 명확한 해결경로가 존재 (신고·상담·소송·중재 등 실제 대처가 서사에 등장하거나 자연스럽게 붙을 수 있음)

일반 막장 사연 선택 로직과 동일한 CVDE 점수 기준을 쓰되, 이 태그가 붙은 사연은 "정보형으로 만들까요?" 선택지로 사용자에게 제시.

### 2. 대본 구조 (draft-narration)

기존 5비트 구조를 그대로 유지하고, 사이다 해결 직후에 **정보카드 비트**를 하나 삽입:

```
훅(3s) → 빌드업 → 반전/폭로 → 사이다 해결 → [정보카드 5~8s: "이럴 땐 [기관명] [번호]"] → CTA(기존 전환장치)
```

정보카드는:
- 나레이션 한 줄 + 화면 텍스트 오버레이로 기관명·전화번호 제시
- 하단에 작은 자막으로 "참고용, 법률 자문 아님" 고지 (안전장치, 아래 §4)

### 3. 메타 태깅 (00_meta.json)

신규 필드 `story_type: "practical_info"` (기존 막장 사연은 필드 생략 또는 `"climax"`로 명시).
목적: analytics에서 두 트랙을 구분 집계해 완주율/좋아요/구독전환 A/B 비교.

## 정보 검증 (핵심 안전장치)

정보카드·고정댓글에 들어가는 기관명·전화번호·법적 근거는 **production마다 WebSearch로 실시간 검증**한다. 고정 DB로 미리 캐싱하지 않는다 — 기관명·번호는 개편될 수 있고, 사연마다 맞는 기관이 다르기 때문.

- 검증 안 된 정보는 **생략** (추측·기억으로 채우지 않는다 — 잘못된 법률/금전 정보는 사용자 피해 + 채널 신뢰도 문제로 직결)
- 검증 소스는 draft-narration 단계에서 별도 WebSearch 호출로 수행, 결과를 `00_meta.json` 또는 production 폴더에 근거 링크와 함께 남긴다

## 길이


- 서사 80~82s + 정보카드 5~8s = **총 85~90s**
- 정보카드 때문에 90s를 넘기지 않는다. 넘을 것 같으면 서사를 압축하지 정보카드를 늘리지 않는다.

## 고정댓글 연동

기존 전환장치 3종(회차번호·다음편떡밥·고정댓글, [[conversion-devices-ab]]) 중 고정댓글에 정보카드의 확장판을 추가:
- 관련 법조항/근거
- 신고·상담 절차 (단계별)
- 상담 가능 시간대 (해당하는 경우)

정보카드는 영상 내 압축본(기관명+번호만), 고정댓글은 확장본 — 두 곳 모두 §의 WebSearch 검증을 거친 동일 출처만 사용.

## 안전장치 (법적 리스크 방지)

- 정보카드 하단 + 고정댓글 양쪽에 "참고용, 법률 자문 아님" 고지 명시
- 신규 FAILURE_CASES 항목 후보로 등재: "정보형 사연 = 미검증 정보 게시 금지" (실제 실패 발생 시 FC 번호 부여해 `docs/FAILURE_CASES.md`에 기록)

## 롤아웃

- 새 채널/새 스킬 없이 **1편 파일럿**으로 시작 (기존 `produce-sayeon` 호출 시 "정보형으로" 선택)
- 완주율/좋아요/전환을 기존 막장 사연과 비교해 서브 트랙 지속 여부 판정
- 판정 데이터는 `story_type` 필드 기반 analytics 쿼리로 축적

## 구현 필드명 (2026-07-14 계획 확정)

| 필드 | 위치 | 타입 | 설명 |
|---|---|---|---|
| `story_type` | `00_meta.json` | `"practical_info"` 또는 생략 | 생략 시 기존 막장 트랙과 동일 취급 |
| `info_card_text` | `00_meta.json` | string | 정보카드 화면 텍스트 (예: `"이럴 땐\n대한법률구조공단 132"`) |
| `info_card_after_line` | `00_meta.json` | int (0-based) | 이 인덱스의 자막이 끝난 직후 정보카드 노출 시작 |
| `info_card_sec` | `00_meta.json` | float, 기본 6.0 | 정보카드 노출 길이(초) |
| `info_card_disclaimer` | `00_meta.json` | string, 기본값 코드에 내장 | 생략하면 `compose_narration.py`가 "⚠ 참고용 정보 · 법률 자문 아님"을 자동 적용 |
| `info_source` | `07_upload_meta.md` 헤더 `**정보검증출처**:` → `_pubmeta.json` | string | WebSearch로 확인한 근거(기관 홈페이지/검색 쿼리). 비어있으면 `story_type=practical_info`일 때 `_warnings`에 게이트 경고 |

정보카드는 CTA/다음편 떡밥 라인보다 **앞**에 와야 한다(`info_card_after_line`이 CTA 라인 인덱스 이상이면 안 됨) — draft-narration이 라인을 쓸 때 순서를 지킨다.
